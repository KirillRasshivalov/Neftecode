# Нефтекод 2026 — мультиагентная система поддержки решений

Цепочка **АВТ → гидроочистка → блендинг**. Система читает состояние установки 24-2000 из
телеметрии и анализов, оценивает возможные изменения режима и выдаёт оператору
объяснимую рекомендацию — или **отказывается**, когда надёжного решения нет. Решение за
9 мс, без внешних сервисов и без языковых моделей в контуре.

Все допущения с причинами — в [`ASSUMPTIONS.md`](ASSUMPTIONS.md), отчёт по данным — в
[`docs/data_audit.md`](docs/data_audit.md).

## Установка

```bash
pip install -r requirements.txt
pip install -e .
```

Python ≥ 3.11, около 4 минут. **На Windows** кладите репозиторий в короткий путь вроде
`C:\Users\<имя>\Neftecode`: в глубокой папке установка `jupyter` падает с `WinError 206`.

## Входные данные

Положите в `data/raw/` три файла из пакета организаторов:

| Файл | Что |
|---|---|
| `242000_tags.csv` | телеметрия 24-2000, колонка `date`, шаг 10 минут |
| `ЛИМС*.xlsx` | лабораторные анализы |
| `*ПАК*.xlsx` | поточные анализаторы |

Система работает на **любой выгрузке установки 24-2000 в этом формате** — за любой
период и любой длины: проверено и на полной, и на трёхмесячной. Нужны теги рычагов `T5`,
`F26`, `F2`, `P13`, теги контекста `F1`, `P3`, `W4`, `F9`, `T16`, `F17`, `T6`, `Q21`,
лабораторная сера `Mg.Sulfur` в точке «Гидроочистка, т.о. 2» и анализатор
`24-2000:Mg.Sulfur`.

Если тега в выгрузке нет, система не падает: без рычага — отказ с названием тега, без
тега контекста — решение принимается без классификатора, по интервальной оценке.
Обучающие скрипты на неполной выгрузке, наоборот, останавливаются с ошибкой, называющей
тег, — чтобы не записать в модель пустые значения.

**Другая установка или другие теги** задаются в одном месте — `scripts/realdata.py`
(рычаги, теги контекста, коды заглушек, точка отбора, сигнал анализатора), после чего
модели переобучаются командами ниже. Смысл тегов система не угадывает: он берётся из
справочника КИП, как требует ТЗ.

## Запуск

```bash
python -m scripts.build_cache            # сырые файлы → data/cache/*.parquet, ~30 с
python -m scripts.analysis.labels        # метки из ЛИМС, обязательно, ~3 с
```

Метки в git не лежат: это выборка из лабораторных данных организаторов. Коэффициенты
моделей лежат — `models/*.json`, так что дальше можно сразу запускать:

```bash
python -m scripts.run_real --week risk                          # неделя, 168 решений
python -m scripts.run_real --at "2026-07-18 16:00" --all-cards  # одна карточка
python -m scripts.run_real --follow --week risk --tick 2        # непрерывный цикл
python -m scripts.blend_scenario --at "2026-07-12 14:00" --feed-sulfur 1.2 --season winter
streamlit run ui/app.py                                         # консоль оператора
pytest                                                          # 133 теста
```

Каждое решение пишется JSON-трассой в `artifacts/real/`: входные данные, оценки всех
агентов, итог. `blend_scenario` — сценарий «что если»: меняются сера в сырье, сезон и
запасы компонентов, система выдаёт рекомендацию по реактору и по смеси.

**Весь пайплайн одним файлом** — `notebooks/neftecode_pipeline.ipynb`, от сырых файлов до
карточки оператора, 134 секунды.

**Переобучение с нуля** — около 2 минут, коэффициенты совпадают с git побайтово:

```bash
python -m scripts.analysis.quality_baseline_fit
python -m scripts.analysis.breach_classifier
python -m scripts.analysis.reliability_reference
python -m scripts.analysis.economics_reference
python -m scripts.analysis.blend_components
```

## Как устроено

```
сырые файлы → кэш parquet → ProcessState на момент t
                                     │   только то, что было известно в t
         агент качества · агент надёжности · агент смеси
                                     │
          оптимизатор  ⇄  жёсткие ограничения (сера по p95)
                                     │
        оркестратор → рекомендация / удержание / отказ → трасса JSON
                                     │
                            консоль оператора
```

Анализ ЛИМС становится видимым через 4 часа после отбора, окна признаков заканчиваются в
момент решения — это проверяет `tests/test_as_of.py`, в том числе обрезкой данных по `t`.
Агенты — чистые функции от состояния: для промышленных данных меняется только построитель
состояния.

## Демонстрация

Четыре недели из отложенной части данных, решение раз в час.

| Команда | С | Что показывает | Итог |
|---|---|---|---|
| `--week stable` | 25.01.2026 | не вмешиваться | 99 % удержание |
| `--week risk` | 12.07.2026 | риск по сере — действовать | 32 % рекомендация |
| `--week degraded` | 02.07.2026 | установка работает, данные отказывают | 14 % отказ |
| `--week shutdown` | 21.06.2026 | установка стоит | 100 % отказ |

## Воспроизводимость

Проверено 21.09.2026 с чистого клона на Python 3.11 против 3.13 рабочей копии, с разными
версиями numpy и scipy: все 672 трассы четырёх недель **совпали побайтово**, переобученные
модели — тоже, ноутбук исполняется без ошибок.

## Структура

```
src/neftecode/   контракт, агенты, безопасность, оркестратор
scripts/         подготовка данных, мост к реальным данным, обучение (analysis/)
configs/         ограничения, веса, спецификация смеси
models/          коэффициенты моделей в JSON
ui/app.py        консоль оператора
notebooks/       весь пайплайн
tests/           тесты
```
